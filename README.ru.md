# WinRE-Manager

**WinRE-Manager** — интерактивная утилита диагностики и восстановления среды Windows Recovery Environment (WinRE). Работает в **Windows PowerShell 5.1** с базовыми дисками GPT/MBR. Если локального образа нет, умеет извлекать `Winre.wim` из установочного ISO Windows.

**[Основная документация на английском](README.md)**

> **Внимание!** Программа может отформатировать или удалить существующий раздел восстановления, а также увеличить C:. **Перед использованием сделайте полный резервный образ диска либо проверенную контрольную точку виртуальной машины.** Автоматического отката нет. Сначала проверьте программу на тестовой VM.

## Запуск

Запустите **`WinRE-Manager.ps1`** через контекстное меню **«Выполнить с помощью PowerShell»** либо из PowerShell командой `& '.\WinRE-Manager.ps1'`. Параметров запуска нет. Если прав администратора недостаточно, скрипт запрашивает UAC и открывает отдельное окно с повышенными правами. Уже открытая исходная консоль не закрывается. `WinRE-Manager.ps1` ждёт нажатия клавиши после окончания работы. Установщик ждёт клавишу только при запуске через проводник; при запуске из уже открытого PowerShell/CMD/терминала сразу возвращается к приглашению. При успешном запуске повышенного экземпляра исходный скрипт завершается без дополнительного ожидания.

Сценарий: **анализ → итоговый план → одно подтверждение `Y/N` → выполнение**. Этапы, предупреждения и результаты разделены отступами и спокойными цветами. Любой ответ кроме `Y` означает отмену. Файлы журналов не создаются. **Все сообщения программы на английском языке.**

Если WinRE уже включена (`Enabled`), программа ничего не изменяет. Если выключена (`Disabled`), сначала проверяется локальный `Winre.wim`. При отсутствии подходящего образа программа попросит подключить установочный ISO соответствующей редакции и сборки, затем указать **букву диска без двоеточия** (`F`). Поддерживаются `sources\install.wim` и `sources\install.esd`.

Редакция сопоставляется по `EditionId`, архитектура — независимо от языка Windows. При выборе ISO программа сначала ищет точное совпадение сборки; для Windows 11 24H2/25H2/26H2 допускает единственный подходящий образ из общего семейства сборок 26100/26200/26300 с предупреждением. Для диагностики выводит индексы, редакции, сборки и архитектуры доступных образов. Образ извлекается во временную папку на C: до подтверждения и проверяется. Минимум для Recovery: `max(990 МиБ, размер Winre.wim + 250 МиБ + 32 МиБ)`. После нажатия `Y` программа сначала пробует обычный `reagentc /enable`. Если он сработает, изменения разделов не выполняются.

## Какие схемы поддерживаются

| Разметка | Действия при невозможности включить WinRE штатно |
|---|---|
| `C: → Recovery → свободное место` | Удаляем старый Recovery, при возможности расширяем C: до целого числа ГиБ и создаём новый Recovery. Уменьшения C: нет. |
| `C: → Recovery → D:` | Если Recovery достаточного размера, форматируем и восстанавливаем WinRE **на том же месте**. C: и D: не изменяются. Если места мало — выходим без переразметки. |
| `C: → свободное место` | Создаём Recovery, если свободной области достаточно. |
| `C: → D:` без Recovery | Пока не поддерживается: программа ничего не перемещает и не уменьшает. |

**Recovery между C: и D: — нормальное и рекомендуемое Microsoft расположение.** Переносить раздел восстановления за D: не требуется. Если размер Recovery недостаточен, в будущей версии планируем уменьшать C: и пересоздавать Recovery перед D:, не затрагивая D:.

При создании нового Recovery программа устанавливает GPT GUID `DE94BBA4-06D1-4D40-A16A-BFD50179D6AC` и атрибуты восстановления, либо MBR тип `0x27`. Максимум для перестраиваемого Recovery — рассчитанный минимум + 1024 МиБ; остаток по возможности отдаётся C:, чтобы его размер был целым числом ГиБ.

## Ограничения безопасности

- Нужны права администратора, Windows на **C:**, Windows 10/11 либо Windows Server 2016 и новее с необходимыми штатными инструментами. Основная цель — Windows 11.
- Устаревший `WinRE-Manager.cmd` после обновления можно удалить вручную: установщик не удаляет посторонние файлы.
- Не трогаем неизвестные разделы и OEM-данные восстановления. Содержимое существующего Recovery должно быть доступно для проверки.
- Не форматируем D:, не перемещаем разделы и не уменьшаем C: в этой версии.
- Не изменяем системные тома с BitLocker или при невозможности проверить его состояние.
- До подтверждения структура диска не меняется; извлечение ISO временно занимает место на C:. Временные файлы создаются в `%WINDIR%\Temp\WinRE-Manager-<GUID>`, а полный путь к WIM показывается перед экспортом. DISM выводит свой штатный индикатор прогресса непосредственно в консоль, без обёртки PowerShell. Скрипт также показывает путь монтирования, путь извлечённого Winre.wim и результат проверки образа, чтобы назначение монтирования и размонтирования было очевидным.
- После ошибки, произошедшей уже после удаления/форматирования, временная копия `Winre.wim` сохраняется для ручного восстановления. Автоматического отката разметки нет.
- При прерывании **Ctrl+C** скрипт пытается очистить временные ресурсы и выводит заметное красное сообщение **OPERATION INTERRUPTED**, а не только приглашение нажать клавишу. Если операции с разделами уже начались, перед повторным запуском необходимо проверить состояние диска и WinRE. Принудительное завершение процесса не гарантирует очистку и вывод сообщения.

## Установка и обновление через GitHub

После публикации репозитория `avmaksimov/WinRE-Manager` в ветке `main` скачайте установщик командой **Invoke-WebRequest**:

```powershell
Invoke-WebRequest -Uri ('https://raw.githubusercontent.com/avmaksimov/WinRE-Manager/main/install.ps1?cacheBust=' + [guid]::NewGuid().ToString('N')) -Headers @{ 'Cache-Control' = 'no-cache'; 'Pragma' = 'no-cache' } -OutFile '.\install.ps1' -UseBasicParsing
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\install.ps1'
```

Установщик загружает ZIP репозитория через `Invoke-WebRequest`. Папка назначения — **текущий рабочий каталог PowerShell** (`Get-Location`), даже если сам `install.ps1` лежит в другой папке. Перед запуском перейдите в нужную папку. Установщик показывает полный путь назначения, автоматически находит файлы в ZIP (включая вложенные папки, но исключая любые файлы и каталоги, имена которых начинаются с точки (например, `.gitattributes`, `.github/`, `.env`, `.config/`) на любом уровне), сравнивает SHA-256 и выводит их по алфавиту относительно корня репозитория: `INSTALL` для новых, `REPLACE` для изменённых, `UNCHANGED` для неизменённых (пропускаются), затем запрашивает **одно `Y/N`**. После подтверждения создаёт необходимые подпапки, подготавливает `.new` рядом с целевыми файлами и заменяет их. При добавлении файлов в репозиторий список в установщике менять не нужно. Старые копии не сохраняются, другие файлы не удаляются. Ранее установленные файлы с точкой в начале имени автоматически не удаляются. Временные файлы загрузки удаляются, собственные журналы в файлы не записываются. Команда с GitHub заработает после публикации репозитория.
